# Known limitations

These are limitations of the implementation at commit
`7d4aa08d0673a03e5d27b667c2653b0632a5bdfa`, not planned features represented as complete.

## Provider and evaluation limitations

* The verified keyless replay run uses committed cassettes whose model field is
  `synthetic-emulator`. They are generated by `app/llm/synthetic.py`, not by a live OpenRouter
  OpenRouter call.
* A live smoke run used the locally configured OpenRouter key: the pipeline validated and
  10 authenticated chat requests returned HTTP 200. This does not establish broad answer
  quality, rate-limit behavior under load, or live cassette reproducibility.
* `evaluation_cases/cassettes/openrouter` is a separate, older recording set. It is not the
  source of the README replay metrics and may miss under the current prompt version; its live
  provenance is not verified in this session.
* Metrics are from one seeded dataset and a small case set. They do not establish hidden
  schema generality or production latency.
* The evaluator reports expected malformed/missing-file cases as `error` while returning
  success for the batch. Consumers must inspect per-case status, not only process exit code.

## Configuration mismatches

`.env.example` sets `LLM_PROVIDER=none`, `LLM_MAX_RPM=20`, and
`OPENROUTER_MODEL=particle-ai/particle-1:free`. Code defaults are `none`, 30 RPM, and
`particle-ai/particle-1:free` when no `.env` overrides them. This is configuration
precedence, not a hidden runtime flag. The README documents both values; a production
submission should choose one canonical example and update the code default if needed.

## Data and scale limitations

* Cleaning currently materializes each dataset as a pandas frame. DuckDB scans and executes
  analytics efficiently, but the cleaning phase is not streaming.
* The repository's 100,000-row scale test passed once on 2026-11-16 (`1 passed`); it does not
  prove the configured five-million-row limit is comfortable on every machine.
* Date disambiguation is intentionally conservative. An interactive approval rerun is
  required before date-based analytics can use an ambiguous column.
* Role inference uses configured aliases, types, distributions, and relationship signals.
  An unseen schema can result in clarification or unsupported output.
* Currency is parsed and labelled according to the available column/metric definition; the
  application does not perform currency conversion, fiscal calendars, or multi-currency
  reconciliation.
* Stock-risk is a registered explainable metric definition, not a trained or operational
  replenishment model.

## Product and operational limitations

* `X-Owner-Id` is a development identity stand-in. Bearer token mapping is available, but
  there is no full user directory, login flow, or role-based authorization system.
* The static UI is intentionally minimal. The API and Swagger interface are more complete
  than the page; there is no streaming response or rich charting.
* The job runner is a single in-process worker. A process restart can lose queued work; a
  durable queue and worker deployment are future work.
* SQLite is suitable for the assessment's local workflow, not a multi-instance production
  deployment.
* The optional cleaning advisor and narrator are bounded seams. They can be disabled, and
  deterministic rule/template paths remain authoritative.

## Observed evaluation outcomes

The verified run on 2026-11-16 produced:

* 12 cases: 10 `ok`, two expected input errors, zero unexpected errors;
* 36 replay cassette hits and zero misses;
* 15 injection attacks, zero successes, ASR 0.0;
* replay first-plan validity 0.9091 because one replayed question needed repair;
* fallback first-plan validity 1.0;
* replay and fallback exact-answer accuracy and grounding both 1.0 on their measured
  questions.

The two expected errors were `bad_case_missing_file` and `bad_case_malformed`. They are
intentional evaluator isolation cases, not hidden failures. The live smoke run is not used
for evaluator quality metrics.

## Future work / not implemented

* Replace the development owner header with authenticated authorization.
* Add chunked cleaning and durable job execution.
* Record a fresh OpenRouter cassette set after freezing the production prompt/model.
* Add richer UI evidence and trace views.
* Add provider retention/configuration controls and operational monitoring.
* Expand hidden-schema, multi-currency, fiscal-calendar, and production-scale evaluation.
